# 完整主提示词：Rust 仿真 + TS 表现 + 等距指挥终端风格

> 设计思路：把约束分成三层——**不变量（硬）** / **默认值（可调）** / **自由区（鼓励发明）**，再加一条「反僵化条款」：每阶段必须加入至少 1 个原创设计点。
> 这样既保证风格不漂、架构不腐，又把发挥空间留给模型。
> 用法：整段提示词 + 参考截图一起给模型；先要设计文档，再分阶段实现。

## 主提示词（整段复制）

```text
# 任务
用「Rust 仿真内核 + TypeScript 表现层」的分层架构，做一个可在浏览器运行的单机 demo：《星区指挥终端 / ORBITAL COMMAND》——等距视角的星球建造 + 太空计划 + 星际物流与舰队对战。
美术风格参考我随提示词附上的截图。注意：它是"风格参考"，要求复刻同一套视觉语法，不要求逐像素临摹。允许并鼓励你在同一语言内发明新资产、新模块、新细节。

# 你的角色
你是同时具备游戏客户端工程、系统架构、界面美术能力的资深工程师。先做设计判断，再写代码：遇到冲突时优先守住"不变量"，其余自由发挥，并在 docs/decisions.md 记录你的取舍与理由。不要机械照搬参考图，也不要为了"稳"把画面做成模板化 UI。

# 一、风格契约
## 不可违反的视觉不变量（8 条）
1) 视角：2:1 等距正交，固定机位，无透视畸变；所有体积物由等距盒体/圆柱/穹顶等基本体拼成。
2) 光影：全图统一左上光；体积物至少三面明暗（顶/右/左 ≈ 1.0 / 0.86 / 0.68）+ 1px 亮棱与暗棱；接触阴影短、柔、统一偏右下。
3) 表面：硬边拼花（瓦片/地砖/金属格栅），材质 = 底色 + 低频噪声 + 细 dither + 1px 暗缝；不同材质硬边相接，不用大面积渐变糊。
4) 材质语言：HUD 是哑光近黑钢板 + 1px 冷钢描边 + 直角（圆角 ≤2px）；禁止玻璃拟态、模糊、大面积泛光、卡片化大圆角。
5) 色彩纪律：压深黑位 + 低饱和；全图只有三种强调角色——主强调（数值/激活/关键动作）、功能色（进度/数据流/连接）、状态色（雷达/正常态）；危险色仅用于警报与敌方。不出现第四种高饱和强调。
6) 排版：中文是信息主体（Noto Sans SC / 思源黑体 700），英文只作宽字距小号副标题；数字与倒计时用等宽；字号约 10–14px 的三档层级；高信息密度、细 1px 分隔线。
7) 素材：全部程序化绘制或内联 SVG 线性图标；零位图、零 emoji、零图标字体。
8) 分工：世界画面用 Canvas 绘制，HUD 用 DOM/CSS 叠加（保证文字锐利、1px 边框）；两者共用同一套色板 token。

## 可以自由发挥的地方（鼓励）
- 星球地貌类型、建筑造型与组合、装饰物、单位与载具设计——只要仍用等距基本体语言。
- HUD 的模块内容、信息层次、图标设计、微动效——只要保持材质、1px 语言、色彩纪律与"标题 + 数据 + 细进度/状态"的三段式面板结构。
- 玩法数值、经济曲线、事件文案、世界观命名。
- 参考图里没有你需要的东西，就发明它；默认参数让画面变丑，就调整它并说明理由。
- 允许提出比本规范更好的技术或视觉方案，但必须给出理由与影响，并保证不变量仍然成立。

## 默认值（可调，不是圣旨；改动请记入 decisions）
- 色板默认：面板 #050C0C / #0B1416 / #1D272B，描边 #4E5C60，主强调琥珀金 #F0C050，功能青 #88D8E8，状态绿 #90C0A0，危险红 #C24A3A。
- 备选色相：冷蓝科技（主强调 #6FC8F0 / 功能 #A0E0D0 / 状态 #7FD8A0）、黄铜蒸汽（#D9A24E / #9CC8B0 / #C8B060）；可先出 2 套对比图再定。
- 版式默认：顶栏约 3% 高；右侧指挥栏约占宽 17%；左下浮动调试面板；底部字幕；地图占其余区域。
- 瓦片默认 64×32（2:1），其他 2:1 尺寸（如 96×48）也允许，全图统一即可。
- 字体默认 Noto Sans SC；英文副标题 10px、字距 .3em；数字等宽、tabular-nums。

## 默认 HUD 组成（可重组，保持三段式结构与三色纪律）
- 顶栏：状态灯 + 星历时钟 + 4 项资源 + 操作提示 + 暂停。
- 右侧指挥栏：上部星区态势小地图（轨道环 + 航线 + 光点）；中部 3 行任务/冷却（名称 + 数值 + 细进度条）；下部 2×2 分类页签 + 建造卡。
- 左下浮动调试台：F3 开关、∞ 资源 / 快速建造、AI 档位三段选择器、脚注。
- 底部字幕：说话人标签 + 台词；战斗时顶部警报条。
- 允许替换/新增模块（例如：航线吞吐图、事件日志、科技树入口），只要仍守三条不变量：哑光黑钢材质、1px 线条语言、三色纪律。

# 二、工程契约
## 架构（不变量）
- Rust 负责全部规则与仿真：crates/iso（纯数学）、crates/content（数据表）、crates/protocol（Command/Snapshot + 版本）、crates/sim（确定性仿真，无 I/O/DOM）、crates/bridge-wasm（薄桥）；可选 crates/server 复用同一套 crate。
- TS 只负责表现：web/src/render（Canvas）、web/src/ui（DOM HUD）、web/src/net（Transport）、web/src/generated（由 ts-rs 生成的协议类型，禁止手写）。
- 单向数据流：输入 → Command[] → sim.step() → Snapshot → 渲染/HUD。渲染与 HUD 不得持有或复制游戏规则。
- 确定性：固定步长、分流域 RNG、禁用 Math.random；同 seed + 同命令序列 → 同状态哈希。
- 协议二进制（bincode/postcard）；WebSocket 用 binary frame；禁止每 tick JSON。
- 内容数据驱动：新增建筑/单位/航线只改 content 表 + 渲染注册，不改系统逻辑；类型系统在编译期强制完备。
- 类型安全：TS strict（禁止 any / @ts-ignore）；Rust clippy -D warnings；协议类型只由 Rust 生成。
- 可观测：debug overlay（fps、tick 耗时、实体数），?debug=1 开启。
- 每个阶段都必须：可运行、可截图、CI 全绿。

## 结构自由度
- 目录分层必须满足上面的依赖方向，但具体文件可按领域拆分/合并；单文件 ≤ 400 行；文件名 kebab-case；只用命名导出。
- 允许在不破坏依赖方向的前提下重构目录；重构必须在一次提交内完成并保持 CI 绿。
- UI 层保持可替换（将来想换 React/Solid 只改 web/src/ui）。

## 接口默认（可扩展、不可删）
- System { name; update(ctx, dt) }
- Command 联合类型：place / demolish / launch / toggle-route / set-sandbox / set-speed / pause
- Snapshot { protocol, tick, hash, resources, entities, events }
- Transport { start; send; onSnapshot; close }（WasmTransport 与 WebSocketTransport 可互换）
- HudModel / HudSnapshot 只读，由渲染与 HUD 派生

# 三、玩法（核心循环，可扩展）
星球地表建造（指挥中心/太阳能/精炼/燃料/发射台/机库/炮塔/货运坪）→ 资源产出 → 火箭发射上轨道 → 星际航线物流 → 敌方舰队周期性来袭 → 防御与再生产。
鼓励扩展：更多星球类型、事件、科技、舰船种类、天气/灾害；但保持"建造 → 发射 → 物流 → 战斗"的闭环，以及"一眼能看懂"的操作简洁。

# 四、协作流程（既防跑偏，也防死板）
1) 先交设计文档（≤2 页）：风格 token 表、架构图、关键取舍、风险与验证方式；此时不写实现代码。
2) P0：脚手架 + CI 全绿（Rust: fmt/clippy/test；前端: typecheck/lint/test/build），协议与类型骨架就位。
3) P1：Rust 仿真五系统 + 单测 + 确定性哈希（headless CLI 可跑 1000 tick）。
4) P2：TS 渲染 + HUD 静态版；截图并与 8 条不变量逐条对照。
5) P3：交互闭环 + 动效 + 性能达标（60fps 渲染 / 30Hz 仿真）。
6) P4（可选）：crates/server + WebSocketTransport + 断线重连。

## 反僵化条款（重要）
- 每个阶段至少加入 1 个原创设计点（新地貌/新建筑/新 HUD 模块/新动效/新交互），并说明它为什么成立。
- 允许对默认参数做最多 20% 的偏离；每条偏离必须能在 docs/decisions.md 找到"改了什么、为什么、影响是什么"。
- 禁止为了省事而删减不变量；也禁止为了"像参考图"而抄它的具体内容。
- 每阶段结束交 3 条自评：守住了哪些不变量 / 偏离了哪些默认值及理由 / 本阶段的创意点。

# 五、验收
- 视觉：8 条不变量逐条自检；与参考图并排，看得出"同一套语言"，但允许是新场景、新资产。
- 工程：依赖方向零违规；协议类型全部生成；新增建筑只改两处；clippy/tsc 零警告；同 seed 状态哈希一致；60fps；无位图请求；中文无乱码；1280/1920 宽不破版。
- 维护性：README + docs/architecture.md + docs/decisions.md 三件套齐全；新人能在 10 分钟内知道"怎么加一个建筑、怎么换 Transport"。

# 六、禁止
位图/emoji/图标字体/外部 UI 框架/游戏引擎；每 tick JSON；在 TS 里写规则；Math.random；单文件堆代码；玻璃拟态/霓虹/3D PBR/全屏扫描线；用参考截图当素材。

# 附：关于参考图
```

## 使用说明（给投喂模型的人）

1. **参考图一定要一起给**：提示词负责规则，图负责质感；只给文字，模型会偏成"通用等距卡通"。
2. **先要设计文档**：让模型先把"风格 token + 架构图 + 取舍"写出来再动代码；这一步能筛掉 80% 的风格跑偏。
3. **分阶段放行**：P0→P3 每阶段看 CI + 截图再继续；不要一次让它写完整个游戏。
4. **反僵化条款是抓手**：如果它做得太死板（比如照抄参考图的建筑布局），就点名要求"本阶段必须给一个原创设计点"；如果它放飞（霓虹/圆角/位图），就让它逐条过 8 条不变量。

## 决策记录模板（docs/decisions.md）

```markdown
# ADR-001 偏离默认色板
- 改了什么：主强调从琥珀金换为冷蓝 #6FC8F0
- 为什么：题材为冰封星球，冷色更符合世界观；对比度已重新验证
- 影响：全部强调色统一替换，不变量 5 的三色纪律仍成立
- 验证：截图对比 + 色板 token 单测（无硬编码色值散落）
```
