# APHELION 现代航天工程图谱：整体美术重做设计

日期：2026-10-24  
状态：待用户批准  
范围：纯代码视觉重做；不改玩法、仿真、协议或内容表

## 1. 意图

当前 a1 已有完整的等距世界和军工终端，但自然地表每格都有暗缝与高频纹理，形成“裂纹棋盘”；建筑共享相近的灰色和厚重底座，远看难以区分；HUD 的小字与低对比配色削弱了完成度。

本次重做要建立一套一眼可辨认的新视觉语言：**现代航天工程图谱**。浅色工程面板、深色数据显示窗、国际橙操作标识与陶瓷白设施共同构成航天工业感。画面依靠大形、材质、光照和信息层级，而不是增加噪点、泛光或第三方素材。

用户已明确选择“整体重做视觉语言”，并把具体方向交给主 agent 决定。

## 2. 目标、非目标与反目标

### 目标

- 同一 seed 的开场截图与旧版有明显代际差异，不再只是旧军工 HUD 换色。
- 在默认 1x 缩放下，16 种建筑可按剪影和结构特征辨认；玩家设施从地表清晰分离。
- 自然地表有连续的大尺度材质变化，没有逐格暗缝、重复印章和平均分布的亮点。
- HUD 正文与功能文字清晰，雷达等内容显示窗保持深色；保留现有操作和面板位置。
- 全部世界与图标仍由 Canvas/CSS/inline SVG 生成，运行时零图片、字体和外部资源请求。
- 增加的静态细节由缓存承担，保留施工、受损、生产和战斗动画。

### 非目标

- 不改建筑 footprint、价格、科技、单位属性、游戏节奏、输入映射或镜头投影。
- 不改 Rust、wasm、二进制协议、生成 fixtures、仿真哈希或版本号。
- 不引入 WebGL、框架、美术库、字体包、图片集或其他新依赖。
- 不重排面板、不做移动端、不改存档或发布流程。

### 反目标

- 不做霓虹赛博、全息蓝紫、玻璃拟态、全屏 bloom、胶片滤镜或颗粒遮罩。
- 不做更脏更乱的废土，不用高饱和草地覆盖矿星，不增加满屏粒子。
- 不用降低文字尺寸、隐藏功能或减少地形细节来伪造性能提升。
- 不把动画建筑整体缓存成静止图片。

## 3. 已比较的方案

1. **仅替换 token**：改动最小，但无法解决地表重复和建筑剪影问题，排除。
2. **保留深色军工 HUD，只重画世界**：风险较低，但观感仍像旧版精修，不符合整体重做，排除。
3. **世界与 HUD 一同重做（选定）**：采用现代航天工程图谱，同时调整材质、造型、图标、雷达与动效，并增加静态建筑缓存。成本最高，但能解决整体观感和长期渲染扩展性。

## 4. 新视觉系统

### 4.2 形状、光照与材质

- 保留 64×32、2:1 等距投影、固定光源与现有相机；不改变拾取坐标。
- 统一左上光。建筑顶面偏暖、左面保持中间调、右面加入轻微冷灰环境色；不得只把灰色乘暗形成“铅块”。
- 陶瓷白主装甲、石墨结构、深色凹槽、国际橙安全标记构成玩家设施。白色只用于实体，不用大面积发光。
- 用少量有意义的分缝、舱门、支座、管道和检修面表现尺度；1px 细纹不得覆盖每个表面。
- 接触阴影短且偏右下；静态主体可用预渲染的有限阶阴影，不使用 blur 滤镜。
- 自然地不再逐格描黑边；技术网格只属于道路、地坪、建造预览和 HUD。

## 5. 世界层重做

### 5.1 连续自然材质

沿用 `ChunkStore → TilePainter → ChunkSurface` 的流送与分帧烘焙，不在每帧计算地形纹理。

- 将 companion mask 从当前 4/2 格高频斑块调整为约 12/5 格的连续变化，降低逐格随机边缘；保持确定性和跨 chunk/环面一致。
- 删除自然地表通用的逐格暗缝。仅 `apron`、`road` 等人工材质保留接缝；材质交界保留稀疏、窄的混合边。
- 删除玄武岩、风化层、苔地、沙地上每格重复的半格矩形“印章”。裂纹、风纹、斑块和岩层相位必须由世界坐标决定，跨格连续。
- 高频 speck 总量减少约 50–70%；细节集中在矿脉、崖壁、道路和设施附近，留白也是材质的一部分。
- 玄武岩采用大板理与冷灰层理；风化层采用暖尘与风向 streak；沙地采用长而稀的波纹；苔地采用成簇低饱和植被，不铺均匀亮点。
- 雪、冻原、沙漠、高地和湿冻原延续现有气候识别，但遵循相同的连续材质规则。
- 浅水、深水保留明暗分层与岸线；水面只画稀疏长波，不逐格画相同短波。
- 晶矿转为烟晶/浅色矿物切面，不做紫色荧光地块。

### 5.2 矿脉、装饰与崖壁

- 金属矿由“散金点”改为有暗色根部、连续脉线、少量明亮切面的铜金矿簇；低丰度稀疏，高丰度才有大晶体。
- 煤矿保持扁平、哑光、黑色层理，与金属矿的立体切面明确区分。
- 岩石、陨坑和石柱强化顶面/侧面与落地阴影；植被降低亮黄绿，避免成为比建筑更显眼的主体。
- 崖壁保留真实 elevation 数据，增强顶棱、岩层和短阴影；不新增仿真皮影或不可见高差。

## 6. 建筑、单位与战斗

### 6.1 建筑造型语言

所有建筑保留 footprint 和当前锚点。共享底座降低厚重黑裙边，改为浅灰混凝土薄台、深色缩进和少量橙色定位角。主体遵循“一个大剪影 + 一个功能部件 + 一处动态信号”，不堆同等权重的小细节。

| 建筑 | 主剪影与识别特征 | 保留/增强的动态 |
|---|---|---|
| 指挥中枢 | 低环形配楼 + 宽檐指挥塔 + 陶瓷白冠部 | 橙色指挥环、天线与数据窗 |
| 光伏阵列 | 四块大倾角蓝黑面板、明显支撑与中央逆变器 | 克制扫光与运行灯 |
| 精炼厂 | 大压力罐 + 深色进料斗 + 侧向输送坡道 | 输送、热槽、少量排气 |
| 燃料合成 | 双球罐 + 细高蒸馏柱与安全色环 | 阀门、压力灯 |
| 研究实验室 | 白穹顶 + 非对称观测舱 | 数据链与状态灯 |
| 发射台 | 八角坪 + 侧塔 + 白火箭 | 火箭高度、尾焰、平台灯 |
| 货运坪 | 大跨度门式吊机 + 分组集装箱 | 吊车、吊钩与航线灯 |
| 中继塔 | 细格构塔 + 小抛物面 | 追踪与信号弧 |
| 轨道炮塔 | 低圆座 + 双长管 | 朝向与充能 |
| 防空炮 | 宽弹药座 + 四管扇面 | 后坐与状态灯 |
| 壁垒 | 低矮厚墙 + 三个清晰射击口 | 就绪灯 |
| 机库 | 大拱顶 + 深舱门 + 橙色门框 | 舱门灯与通风 |
| 雷达阵列 | 设备舱 + 大抛物面 | 旋转与扫描弧 |
| 维修站 | 开放双龙门架 + 中央维修位 | 焊接点、维修无人机 |
| 煤矿 extractor | 大斗轮 + 斜输送 + 深色料斗 | 斗轮、皮带与少量煤尘 |
| 燃煤电厂 | 大锅炉 + 高烟囱 + 橙色炉口 | 炉光、皮带与几何烟气 |

### 6.2 单位与效果

- 玩家单位沿用陶瓷白/石墨主体与青色数据灯；敌方使用暗红结构及红色识别灯，不靠全屏红雾识别。
- 保留七类单位的不同外轮廓，减少 tiny outline 层数，让默认缩放下先读形、再读灯。
- 弹道采用一帧清晰核心线与短衰减尾迹；命中用少量定向碎片和短闪光；爆炸用分阶段几何形与少量烟气，不做大面积泛光。
- 施工、受损、生命条、选中、放置合法性、警报 ping 的语义不变，颜色适配新 `SIGNAL`/UI ramp。

## 7. HUD 与图标

- 保持顶栏 34px、右栏 336px（窄屏 300px）、底部字幕、沙盒位置、面板顺序和全部控件；只重做视觉与内部间距。
- 面板改为暖白连续工程纸张，深墨文字、细分隔线和直角结构；不使用玻璃、圆角卡片或大阴影。
- 雷达、建造缩略图、单位肖像保留深色“内容显示窗”，形成浅面板/深视窗的统一对比。
- 正文 12px、标题 14px、重要数字 14/26px；英文辅助字优先 10px，字距从过宽的 0.3em 收到约 0.16–0.20em。不能用 9px 低对比文字承载关键状态。
- 国际橙只强调激活与关键动作；深青用于数据；绿只表示正常；红只表示敌方/危险。
- 16 个建筑与 7 个单位缩略图从单一线性图标升级为双色等距剪影 SVG：大形与世界建筑一致，仍使用 currentColor/token，无 emoji、图标字体或图片。
- 雷达保持本地 96 格、真实地形采样和动态扫描；背景明确使用 void 与 SIGNAL，不跟随浅面板变浅。中枢定位使用 footprint 的真实中心。

## 8. 渲染结构与缓存

### 8.1 静态主体与动态部件分离

将当前 `BuildingPainter` 注册表逐步升级为每类建筑的 `BuildingArt`：

- `body(env, cx, cy, def)`：只能读 Canvas、固定几何和 def，不读 time 或 BuildingView；负责底座、静态主体与固定细节。
- `motion(env, cx, cy, view, def)`：负责雷达盘、炮管、火箭、斗轮、吊车、灯带、烟气等动态部分。
- 外层统一处理施工与受损；两者不得进入静态缓存。
- 注册表继续以生成的 `BuildingKey` 保证 16 类全覆盖，缺一类仍然 TypeScript 报错。

### 8.2 有界静态精灵缓存

新增 Canvas sprite cache，只缓存 `body`：

- key = building key + raster scale；raster scale 根据 dpr×zoom 以 0.5 档量化并限制在 1–3。
- 每类定义统一逻辑包围盒和地面锚点；body 与 motion 使用同一取整锚点，防止分离。
- 高分辨率离屏绘制，blit 时按逻辑尺寸画回；地形保持硬边，精灵 blit 可开启平滑并立即恢复状态。
- LRU 总预算 8 Mpx（约 32MB）；现有地形预算 24 Mpx（约 96MB）不提高。
- 首次使用才生成；缩放档变化才重建，禁止按 entity id、time、HP、progress 或 charge 建 key。
- 若某部件依赖 view/time，它必须移到 motion，而不是扩大 cache key。

小型单位仍以直接矢量绘制为主；不为它们增加另一套缓存系统。

## 9. 工程约束

- 零新依赖；不增加网络请求，不使用 `Math.random`。视觉随机仅由世界坐标哈希和固定 salt 决定。
- 保持 ESLint 分层：render/ui 不访问 app/net；表现层不推导游戏规则。
- 所有手写 Rust/TS/CSS/MJS/TOML 文件 ≤400 行。当前 `landmarks.ts`、`detail.ts`、`panels.css` 已接近上限，实施前先拆 body/motion 或 fab/readout 样式，不能先堆到超限再补救。
- 更新所有描述旧视觉行为的注释与文档；历史 prompt pack 要明确标为旧版参考资料，不能继续冒充当前规范。
- README/文档截图可以是由真实运行画面生成的 PNG，仅作文档，不进入 `web/` 或运行时。

## 10. 验收与验证

### 自动验证

最终交付必须在当前工作树运行并通过完整 `node scripts/ci.mjs`，包括 Rust 测试与确定性、行为哈希门禁、wasm build、TS typecheck、ESLint、Vitest、Vite build、文件长度、纯代码资产、BOM 和双 exe 打包。

在现有 Vitest 中增加针对新纯逻辑的测试，不引入 DOM 模拟依赖：

- 色板关键文字/背景组合对比度 ≥4.5:1。
- 连续材质函数的确定性、边界输入和合理的斑块尺度。
- sprite cache 的 key 量化、锚点/包围盒与 LRU 像素预算。

不得为通过测试而削弱阈值。现有 chunk、环面、picking、postcard 测试必须原样通过。

### 实机视觉与交互

用真实应用而非孤立 import 验证：

- 同 seed、同构图记录 before/after；检查 1280×720 与 1920×1080。
- 覆盖开场基地、自然/水域/雪地接缝、建造预览、施工、受损、单位交战、火箭发射和雷达跳转。
- 点击每类建筑与至少一个单位；确认视觉中心、选择和拾取未偏离。
- 页面无启动失败、无持续 fatal、无明显破版；Network 无图片/字体/外部请求。
- 页面保持可见以避免后台 rAF throttle；预热后在 demo 与交战场景各观察至少 10 秒，目标 FPS ≥55，且无持续 cold chunk 或动画冻结。
- 浏览器和 WebView2 桌面路径各至少启动一次；无法实际执行的项目必须明确报告，不能宣称通过。

## 11. 实施顺序

1. **基础**：新 token/SIGNAL、对比度测试、光照与共享形状、CSS 和建筑 body/motion 拆分准备。
2. **世界**：连续材质、矿脉/装饰/崖壁、建筑静态主体与动态部件、缓存。
3. **HUD**：浅色面板、深色显示窗、等距 SVG 缩略图、雷达和状态反馈。
4. **联合验收**：真实画面审查并微调，不以“代码完成”代替视觉验收；随后跑完整 CI、实机双路径、更新文档截图。
5. **交付**：主 agent 审查全部 diff，提交、推送、打包并盯远端 CI；任何子 agent 的自报结果都必须独立复核。

## 12. 留给实现者的决定

实现者可以调整不影响方向的几何尺寸、单个材质纹理配方、具体阴影层级和拆分文件名，以截图与性能结果为准。不得自行改变选定的浅 HUD/深视窗方向、四类强调角色、footprint/协议/玩法、缓存预算或验收阈值。

没有需要用户继续回答的美术方向问题。实现期间若出现“必须改玩法或引入依赖才能继续”的情况，应停止该方案并报告，而不是静默扩大范围。
