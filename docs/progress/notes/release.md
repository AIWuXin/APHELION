# 发版流程与版本说明规范（2026-10-22 起生效）

**用户规则：以后每次发版，版本说明都要写清楚「特性 / 修复 / 其他」等模块。**

## 固定流程
1. 版本号：Cargo/npm 用 semver（`0.1.0-a1`），展示与产物文件名用紧凑形（`0.1.0a1`）；单一事实源 `crates/protocol/src/version.rs` 的 `PRODUCT_VERSION`，其余位置派生。
2. 全绿 CI（15 步，含 exe 打包）→ 实跑验收（构建戳/版本号可见、截图留证）→ commit/push → tag `v<展示版>` → GitHub Release 上传两个 exe（桌面版主产物 + 浏览器兜底版）。
3. Release 正文固定分节：`## 特性` / `## 修复` / `## 其他`（工程与文档），逐条一句话，写用户能感受到的变化，不堆内部细节。
4. 产品名：**远日点**（英文代号 APHELION），不再用「远日点指挥终端」；「指挥终端」只作为 HUD 风格/剧情设定的描述词保留。
